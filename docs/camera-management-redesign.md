# 카메라 추가·관리 리메이크 기획

작성: 2026-10-18. 대상: CamFloat - RTSP Stream Viewer, RC2 이후.
상태: RC3 구현 반영. 아래 원안 중 후속 사용자 요청과 다른 항목은 다음 최신 결정으로 대체합니다. 실제 Windows Hello 인증·실카메라 제어는 미검증입니다.

## 최신 결정 · 관리화면 정리

- 디자인 후속 변경: 관리창 820×540, 추가창 520×420, 입력칸 높이 28px. 공통 상단 라벨·정렬·간격, 주소/포트·아이디/비밀번호 묶음, 한 줄 하단 버튼. 입력 방식·고급 설정에 따라 추가창 높이 조절.
- 주소·아이디는 기본 가림으로 복원하고 인증 없이 보기·복사. 비밀번호·RTSP는 인증 필수. 복사 아이콘은 입력칸 안에 배치하며 ⋯ 메뉴의 복사는 제거. 빈 항목은 보기·복사 비활성화. 아래 이전 결정에서 다른 내용은 이 두 항목으로 대체.
- 상세는 이름 → 주소 → 아이디 → 비밀번호 → RTSP 주소 → RTSP 주소2 (SD) 순서. 주소·아이디는 바로 표시하고 재생·배정 요약은 제거.
- 비밀번호와 RTSP 주소는 Windows 본인인증 필수. 편집·복사 경로도 동일하며 인증 해제 설정은 제거.
- 별도 RTSP 복사 버튼, 수정·사용 여부 버튼 제거. 관련 동작은 목록 ⋯ 메뉴에 배치.
- 추가하고 계속 제거. 빈/입력 중 RTSP 주소도 간편 입력으로 복귀 가능하고 임시 입력 보존.
- 고급 설정 명칭: 영상 경로 (HD) / 영상 경로 (SD). SD는 상대 경로 또는 별도 RTSP 주소 지원.
- 관리 집중 검사 9개 통과. 인증 성공/실패/만료는 모의 응답으로 검사했으며 실제 Windows 인증을 대신하지 않음.

## 1. 목적과 기본 결정

- 목록을 열거나 화면을 공유할 때 IP·도메인·계정·비밀번호가 바로 노출되지 않게 한다.
- 사용자는 저장한 연결 정보를 다시 확인·수정·복사할 수 있어야 한다.
- 기본은 자동 가림, 항목별 명시적 확인, 30초 후 재가림이다.
- 같은 Windows 로그인 세션을 조작할 수 있는 다른 사람까지 막으려면 선택적으로 Windows 본인 확인을 추가한다. 단순 눈 아이콘은 본인 확인이 아니다.
- 일반적인 카메라 지정·순서 변경·음량 조절에는 인증 절차를 붙이지 않는다.
- 영상 재생은 기존 구조를 유지한다. 관리 UI 수정 때문에 재생 엔진이나 HWND 구조를 바꾸지 않는다.

## 3. 카메라 관리 화면

권장 크기 960×640, 최소 760×520. 작은 작업 영역에서는 상세 영역을 접거나 스크롤한다.
현재의 어두운 색상·파란 강조색·아이콘 체계를 유지한다. 애니메이션과 장식용 배경은 추가하지 않는다.

```text
카메라 관리                                      [+ 카메라 추가]

 [카메라 목록]  [화면 배정]

 [번호·별명 검색                           ] [전체 / 사용 / 사용 안 함]

 ┌ 카메라 목록 ──────────────────┬ 선택한 카메라 ─────────────────┐
 │ 01  거실        HD   사용  ⋯  │ CAMERA 01 · 거실                │
 │ 02  현관        HD   사용  ⋯  │ 현재 재생 상태 / 배정된 SCREEN   │
 │ 03  창고        SD   꺼짐  ⋯  │                                 │
 │                              │ 연결 정보                       │
 │                              │ 주소      숨김            [눈]  │
 │                              │ 아이디    숨김            [눈]  │
 │                              │ 비밀번호  ••••••••        [눈]  │
 │                              │                                 │
 │                              │ [카메라 수정]       [정보 복사 ▾]│
 └──────────────────────────────┴─────────────────────────────────┘

 등록 3대 · 사용 2대                   [취소] [저장하고 적용]
```

- 목록의 핵심은 번호·별명·화질·사용 상태. 주소와 긴 설명은 넣지 않는다.
- 번호는 등록된 카메라 번호이며 순서를 바꿔도 유지한다.
- 위·아래 이동은 선택 행에 대한 작은 도구로 제공한다. 검색/필터 중에는 전역 순서 이동을 잠그고 이유를 툴팁으로 표시한다.
- 삭제는 행의 ⋯ 메뉴 아래에 두고 확인한다. 사용 안 함은 삭제와 다른 동작임을 명확히 한다.
- 상태는 현재 재생 중인 세션에서만 읽는다. 연결한 적 없는 카메라는 `미확인`으로 표시한다.
- 관리 화면을 여는 것만으로 미사용 카메라에 접속하거나 미리보기를 시작하지 않는다.
- 빈 목록은 `등록된 카메라가 없습니다`와 추가 동작을 표시한다.
- 검색은 기본적으로 번호·별명만 검색한다. 주소 검색은 기본 범위에서 제외한다.

## 4. 화면 배정 탭

- 상단에서 1분할 / 2분할 / 4분할을 선택한다.
- 선택한 분할 모양에 맞춘 SCREEN 카드 안에서 카메라를 지정한다.
- 2분할 좌우·상하는 같은 배정을 사용한다는 짧은 안내를 둔다.
- 이미 다른 SCREEN에 있는 카메라를 지정하면 기존 규칙처럼 서로 자리를 바꾼다.
- `화면 비우기`를 명시적으로 선택할 수 있다.
- 사용 안 함은 모든 분할의 배정을 해제한다. 다시 사용하면 각 분할의 빈 SCREEN부터 채운다.
- 빈칸이 없으면 기존 카메라를 밀어내지 않는다.
- 카메라 순서와 SCREEN 배정은 별도 개념으로 유지한다.
- 관리 화면에서 편집할 분할을 바꿔도 실제 플레이어 분할은 저장 전 바꾸지 않는다.

## 5. 카메라 추가·수정

입력 방식은 상단의 `간편 입력 / RTSP 주소` 선택으로 제공한다.

### 간편 입력

1. 별명: 비워도 등록 가능. 기본 이름은 카메라 번호로 생성하고 호스트를 넣지 않는다.
2. IP / 도메인, 포트: 포트 기본값 554.
3. 아이디, 비밀번호: 비밀번호는 항상 기본 가림. 새 주소를 직접 입력할 때는 확인하며 입력하고 저장 후 가림으로 전환한다.
4. 스트림: ipTIME 기본 HD /onvif1, SD /onvif2. 사용자 지정 경로는 고급 항목으로 제공한다.
5. 기본 화질: HD / SD. SD를 제공하지 않으면 이유를 표시한다.

### RTSP 주소

- 전체 주소 붙여넣기를 지원하고 기본적으로 가려서 표시한다.
- 주소를 붙여넣은 뒤에도 전체 주소를 상단 요약·별명·알림에 재출력하지 않는다.
- 호스트·인증·경로·쿼리의 구조를 검증한다. 값 자체를 오류 메시지에 넣지 않는다.
- 두 입력 방식의 전환으로 특수문자·퍼센트 인코딩·IPv6·쿼리가 달라지지 않아야 한다.
- 변환이 불가능하거나 손실 가능성이 있는 사용자 지정 주소는 전체 주소 방식을 유지한다.
- SD 전체 주소는 접힌 고급 설정에서 선택적으로 입력한다.

### 저장 흐름

- 자식 창의 동작은 `목록에 추가` / `변경 반영`으로 표현한다. 여기서는 관리 화면 초안만 바뀐다.
- 여러 대 등록은 `목록에 추가하고 계속`을 제공한다. 로그인 정보는 자동으로 다음 카메라에 복제하지 않는다.
- 관리 창에서 `저장하고 적용`을 누르면 최종 저장하고 플레이어에 적용한다.
- 미저장 변경이 있는 상태로 취소/닫기 시 저장·버리기·계속 편집을 선택한다.
- 최종 저장 실패 시 초안을 보존하고 성공으로 닫지 않는다. 기존 재생 설정을 유지한다.
- 같은 접속 대상 중복은 안내하되 기존 항목을 자동으로 덮어쓰지 않는다.

## 6. 연결 테스트

- `연결 확인`은 사용자가 눌렀을 때만 수행한다. 등록에 성공을 강제하지 않는다.
- 저장하지 않은 초안을 임시 세션으로 확인하며 실제 플레이어 배정은 바꾸지 않는다.
- 처음에는 음소거로 영상 수신 가능 여부를 확인한다. 자동 미리보기는 제공하지 않는다.
- 확인 중 / 영상 수신 확인 / 시간 초과 / 연결 실패를 구분한다.
- 엔진이 구분해 주지 않은 실패를 비밀번호 오류로 단정하지 않는다.
- 시간 제한·취소·창 닫기 시 임시 세션을 정리한다. 창은 멈추지 않아야 한다.
- 실제 카메라를 대상으로 검증할 때는 승인된 카메라만 사용한다.

## 7. 정보 가림과 확인

| 항목 | 기본 상태 | 확인 동작 |
| --- | --- | --- |
| 번호·별명·화질·사용 | 표시 | 추가 동작 없음 |
| IP·도메인 | `주소 숨김` | 해당 눈 아이콘으로 30초 공개 |
| 아이디 | `아이디 숨김` | 해당 눈 아이콘으로 30초 공개 |
| 비밀번호 | 고정 길이 마스크 | 해당 눈 아이콘으로 30초 공개 |
| 전체 RTSP / SD 주소 | 숨김 | 고급 상세에서 해당 항목만 공개 |

- 한 항목을 열어도 다른 항목은 공개하지 않는다. 전체 공개 체크박스는 제거한다.
- 공개 상태는 설정에 저장하지 않는다. 공개 중에는 눈 아이콘을 해제 상태로 표시하고 작은 `숨기기` 동작을 제공한다.
- 30초 경과, 다른 앱으로 전환, 카메라 선택 변경, 관리 탭 변경, 창 닫기, Windows 잠금 때 재가림한다.
- 앱 내부의 드롭다운·팝업으로 포커스가 옮겨지는 것은 다른 앱 전환으로 오인하지 않는다.
- 재가림은 표시만 바꾼다. 입력 중인 값·커서·저장 여부는 바꾸지 않는다.
- 일부 IP 대역을 남기는 부분 마스킹보다 전체 숨김을 기본으로 한다.
- 마스크 문자열을 실제 비밀번호로 저장하지 않도록 값과 화면 표시를 분리한다.
- 툴팁·접근성 이름·행의 숨겨진 문자열·오류·검색 기록을 통한 우회 노출도 확인한다.
- 별명에 주소를 직접 넣은 경우까지 자동으로 안전하다고 안내하지 않는다. 기존 호스트형 별명은 전환 화면에서 탐지해 이름 변경을 제안하고, 확인 전에는 표시를 가린다.

## 8. 복사 정책

- 선택한 카메라 상세에 `RTSP 주소 복사` 동작을 제공한다. 기본 동작은 해당 카메라에 설정된 화질의 실제 재생 주소 복사다.
- 펼침 메뉴에 `HD RTSP 주소 복사` / `SD RTSP 주소 복사`를 제공한다. 지원하지 않는 SD는 비활성화하고 이유를 안내한다.
- 복사 값은 아이디·비밀번호·호스트·포트·경로·쿼리를 포함하는 전체 RTSP 주소다. VLC 등에 그대로 붙여넣을 수 있도록 재생 엔진과 같은 주소 생성 함수를 사용하고 퍼센트 인코딩을 유지한다.
- 미배정·미접속 카메라도 저장된 정보로 복사할 수 있다. 복사를 위해 카메라에 접속하지 않는다.
- 복사 성공 안내는 `RTSP 주소를 복사했습니다`만 표시하고 원문 주소를 알림에 출력하지 않는다.
- 별명 복사, 주소 복사, 비밀번호 복사, 전체 RTSP 주소 복사를 구분한다.
- 전체 주소에는 로그인 정보가 포함될 수 있음을 짧게 표시한다.
- 숨김 상태의 Ctrl+C나 우클릭 기본 메뉴가 저장된 비밀을 바로 복사하지 않게 한다.
- 민감 정보 복사는 전용 동작을 거쳐 수행한다. 강화 보호를 켜면 이 동작에도 같은 인증을 요구한다.
- Windows 클립보드 기록/클라우드 동기화 제외 형식을 함께 설정한다.
- 30초 후 현재 클립보드가 앱에서 복사한 항목과 동일할 때만 지운다. 사용자가 이후 복사한 다른 내용은 지우지 않는다.
- 이미 외부 프로그램이 가져간 사본까지 회수할 수 있다고 안내하지 않는다.

## 9. 선택 기능: 연결 정보 확인 시 Windows 본인 확인

- 기본값 끔. 화면 가림만으로 부족한 사용자를 위한 설정이다.
- 켜면 저장된 주소·계정·비밀번호의 확인·복사·편집을 공통 인증 경로로 보호한다.
- 카메라별 눈 아이콘, 전체 주소, SD 주소, 입력 방식 전환이 우회 경로가 되지 않게 한다.
- 인증은 Windows가 제공하는 PIN/Hello 등의 확인 기능을 검토한다. 별도 앱 PIN은 이번 범위에 넣지 않는다.
- 인증 취소·실패·지원 불가일 때 기존 비밀은 공개하지 않는다.
- 인증 성공은 짧은 관리 세션에만 유효하며 다른 앱 전환·잠금·관리 창 닫기 시 해제한다.
- DPAPI 저장 암호화와 UI 인증은 별도 기능이다. 본인 확인을 꺼도 자동 가림·암호화 저장은 유지한다.
- 같은 사용자 권한의 악성 프로그램이나 관리자에 대한 비밀 보관소 수준의 방어를 보장하지 않는다.

## 10. 저장·백업·이관

- 기존 기본/SD URL DPAPI 암호화를 유지한다. 카메라 ID·번호·분할 배정·음량·음소거는 그대로 이관한다.
- 문자열을 해시로만 저장해 사용자가 재확인하지 못하게 하는 방식은 사용하지 않는다.
- 새 연결 모델을 도입해도 원본 RTSP 주소의 손실 없는 왕복을 먼저 보장한다.
- 정상 백업뿐 아니라 구버전 이관·손상본·임시 파일·오류 처리의 평문 경로도 점검한다.
- 읽을 수 있는 구버전 평문 설정은 검증·암호화 백업을 만든 뒤 원본 정리를 설계한다.
- 해석 불가능한 손상본은 무작정 삭제하지 않고 보호된 보관과 복구 경로를 제공한다.
- 복호화 실패한 항목은 연결 정보 확인 필요 상태로 남기고 덮어쓰거나 자동 재저장하지 않는다.
- 다른 PC/Windows 계정으로 이동할 때 재입력이 필요할 수 있음을 안내한다. 이관용 내보내기는 별도 기능으로 다룬다.

## 11. 코드 구조 제안

- CameraManagerDialog: 탭·선택·초안·최종 적용.
- CameraListModel: stable ID 기반 목록. 화면에 필요한 표시 정보만 전달하고 기본 모델 역할에 전체 URL을 넣지 않음.
- CameraEditorDialog / CameraDraft: 입력 상태·유효성 검증·중복 확인. 현재 입력 방식과 실제 URL 값을 분리하되 단일 기준 데이터를 유지.
- SensitiveField: 항목별 가림·일시 표시·편집·안전 복사의 공통 UI.
- PrivacyController: 공개 타이머·앱 비활성·관리 세션·선택 인증을 통합 관리.
- SecureClipboard: 소유권 확인, 시간 제한, Windows 기록 제외.
- ConnectionProbe: 기존 재생기와 독립된 취소 가능한 연결 확인 작업.
- ConfigRepository: 암호화·백업·원자적 저장·마이그레이션.

현재 dialogs.py에 더 많은 분기와 보안 타이머를 몰아넣지 않는다. 기존 worker를 재사용할 때도 수명 관리와 취소 처리를 분리한다.
Qt/Python 문자열과 VLC 재생 메모리에서 비밀을 완전히 제거한다고 주장하지 않는다.

## 12. 구현 순서와 완료 기준

1. 표시 정책·주소형 별명·공통 민감 필드 구현.
2. 카메라 목록/화면 배정 레이아웃 개편.
3. 추가·수정·여러 대 등록·미저장 변경 처리.
4. 안전한 복사와 로그·백업 경로 보강.
5. 수동 연결 확인. Windows 본인 확인은 선택 기능으로 별도 반영.

향후 검증 기준:

- 관리 목록을 처음 열어도 실제 주소·계정·비밀번호가 화면/툴팁에 나타나지 않음.
- 저장한 정보를 항목별로 다시 확인·수정·복사할 수 있음.
- 공개 만료·다른 앱 전환·탭/선택 변경 때 재가림하며 편집값은 보존됨.
- 입력 방식 왕복으로 특수문자·IPv6·쿼리·SD 주소가 바뀌지 않음.
- 암호화된 설정·백업·진단에 실제 URL/계정이 평문으로 남지 않음. 사용자 별명에 포함된 주소는 별도 정책으로 처리.
- 메타데이터 수정·순서 변경·관리 창 열기만으로 영상 재연결하지 않음.
- 여러 대 추가 후 부모 취소/저장 실패의 결과가 명확하고 복구 가능함.
- 1·2·4 배정, 사용 안 함/다시 사용, 화면 비우기 규칙이 유지됨.

## 기술 참고

- [Microsoft: Clipboard Formats](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats): CanIncludeInClipboardHistory / CanUploadToCloudClipboard.
- [Microsoft: RequestVerificationForWindowAsync](https://learn.microsoft.com/en-us/windows/win32/api/userconsentverifierinterop/nf-userconsentverifierinterop-iuserconsentverifierinterop-requestverificationforwindowasync): 데스크톱 창에 대한 사용자 확인 API. 구현 전에 대상 Windows 지원 여부 확인.
