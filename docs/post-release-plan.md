# 릴리즈 이후 개발 계획

상태: 후속 작업 메모. 앱 기능·배포본은 변경하지 않음.
기준: 음성 간섭을 수정한 1.0.0, 커밋 `09441ec`.

## 1. 수정 확인과 릴리즈 전체 검증 분리

### 운영 원칙

- 일반 수정은 변경한 기능과 직접 영향을 받는 기능만 짧게 확인한다.
- 전체 QC는 릴리즈 직전, 관련 기능의 집중 검사가 먼저 통과한 상태에서 실행한다.
- 집중 검사 실패는 해당 검사로 수정·재확인한다. 수정 중 전체 검사를 반복 실행하지 않는다.
- 전체 검사에서 문제가 발견되면 해당 기능 검사로 원인을 해결한 뒤 릴리즈 최종 검증으로 돌아간다.
- 테스트 계획·결과에는 종류, 개수, 소요 시간과 생략 범위를 표시한다.
- 문서만 변경하면 문서·링크·diff 확인으로 끝낸다. 앱 전체 검사·빌드를 실행하지 않는다.

### 다음에 만들 간단 검사 구성

| 단계 | 사용 시점 | 범위 | 목표 |
| --- | --- | --- | --- |
| 문서 확인 | 문서 수정 | 변경 내용·링크·민감 정보 | 수 초 |
| 기본 간단 검사 | 일반 수정 | 기본값·핵심 모델·앱 시작/종료 | 5~15초 목표 |
| 기능별 검사 | 관련 기능 수정 | 음성 / 관리 / 메뉴 / 창 조작 등을 선택 | 필요한 기능만 |
| 최종 릴리즈 QC | 릴리즈 직전 | 전체 회귀 + 합성 RTSP + 최종 ZIP/EXE | 전체 실행 |

- 기능별 검사를 선택하는 통합 실행 명령과 결과 요약을 다음 작업에서 구현한다. 현재 통합 간단 검사 명령이 이미 만들어진 것은 아니다.
- 이미 분리한 `tests/test_audio_isolation.py`는 실제 출력 음량·음소거를 검증하는 3개 검사이며 약 5~6초였다. 이 패턴으로 다른 기능도 분리한다.
- 정식 검사는 화면별 실제 출력, 영상 픽셀 갱신, 연결 중단/복구, 최종 압축 해제 EXE를 포함한다. 설정 사전이나 증가하는 통계만으로 실제 출력 성공을 판정하지 않는다.
- 실제 카메라·마이크·방향 제어는 일반 간단 검사에서 자동 실행하지 않는다.

## 2. 문서 정리와 GitHub 공개 릴리즈 준비

### 현재 확인

- 최신 실행 파일·ZIP·체크섬과 로컬 태그 `v1.0.0`은 있다.
- GitHub `xogn1004/CamFloat`를 비공개로 생성하고 원격 저장소를 연결했다. 공개 전 릴리즈 초안을 준비한다.
- 사용자 결정: 공개 소스 + 실행 파일 무료 배포, CamFloat 자체 코드는 MIT 라이선스. 루트 `LICENSE`에 반영했다.
- 사용자 배포 ZIP은 EXE·런타임·라이선스·시작 안내만 포함한다. 개발 MD를 ZIP에 추가하지 않는다.

### 준비할 일

1. README는 사용자용 실행·기능·스크린샷·설정 보호·업데이트 안내 중심으로 정리한다. 빌드/검사 지침은 개발 문서로 분리한다.
2. 긴 코드 리뷰와 설계 문서에는 현재 유효한 내용과 과거 기록을 구분한다. 폐기된 초기 1.0.0 후보를 최신 결과처럼 보이게 하지 않는다.
3. CamFloat의 소스 공개 범위·LICENSE·GitHub 저장소를 정하고, 배포에 포함하는 라이브러리의 고지·소스 제공 방식도 최종 확인한다.
4. 추적 파일뿐 아니라 Git 이력도 주소·비밀번호·개인 경로·실카메라 캡처·사용자 설정의 공개 여부를 점검한다. 예시는 합성 데이터만 사용한다.
5. `.venv`, `vendor`, 사용자 설정, 진단 기록, 테스트 미디어·캡처를 공개 소스/릴리즈에 섞지 않는다. 앱 공통 파일 키는 사용자 비밀키로 취급하지 않으며 기존 `.camfloat` 호환성을 위해 임의로 교체하지 않는다.
6. `.camfloat`는 파일 비밀번호 없이 다른 CamFloat에서 열 수 있다는 공유 정책을 사용자 문서에 유지한다.
7. GitHub Release에는 최종 ZIP·SHA-256·짧은 릴리즈 노트·필요한 소스 제공 자료를 연결한다. 태그·커밋·EXE·ZIP·검사 기록의 일치를 확인한다.
8. 공개용 릴리즈 설명과 파일을 준비한 뒤 공개 작업을 진행한다. 이 메모 단계에서 저장소 생성·push·공개는 실행하지 않는다.

## 3. 소리 150% / 200% 증폭

### 가능성

- 현재 libVLC 3.0.23의 DirectSound 구현은 100%를 넘는 값에 소프트웨어 증폭을 적용하는 경로가 있다. 150%·200%를 지원하는 방향으로 검토 가능하다.
- 현재 CamFloat는 슬라이더·음량 설정·설정 파일 정규화·`.camfloat` 내보내기 검증에서 최대 100으로 제한한다. 슬라이더만 늘려서는 저장·공유까지 완성되지 않는다.
- 엔진의 음량 %는 실제 신호 배율·사람이 느끼는 크기와 단순 비례하지 않는다. 숫자 표시와 증폭량의 기준도 확인한다.

### 검토 및 시험

1. 합성 작은 신호로 100/150/200의 실제 증폭, 잡음 증가·찢어짐·피크 잘림을 측정한다.
2. 화면별 증폭이 다른 화면에 영향을 주지 않는지, 음소거·전체 음소거·확대·재연결 뒤에도 유지되는지 검사한다.
3. 기본 최대치는 100으로 유지할지, 고급 설정에서 증폭을 켜면 200까지 허용할지 UI를 결정한다. 100 지점을 분명하게 표시한다.
4. 작은 화면의 세로 슬라이더 정밀도와 휠 간격을 확인한다.
5. 설정 저장·이전 설정 불러오기·`.camfloat` 버전 호환을 설계한 뒤 함께 변경한다.
6. 필요한 경우 출력 피크를 제한하는 처리도 검토한다. 값만 늘리고 음질이 좋아졌다고 판정하지 않는다.

근거: [libVLC 3.0.23 DirectSound VolumeSet](https://github.com/videolan/vlc/blob/3.0.23/modules/audio_output/directsound.c).

## 4. 방향 전환·카메라 ON/OFF·마이크 전송

대상 모델은 아직 ipTIME C400GS로 추정한다. 실제 모델·펌웨어를 먼저 확인한다.

| 기능 | 공식 제품 기능 | CamFloat 외부 제어 상태 |
| --- | --- | --- |
| 방향 전환 | 좌우 360°·상하 150°·저장 위치 | ONVIF PTZ 또는 제조사 인터페이스 확인 필요 |
| 카메라 ON/OFF | 앱의 사생활 보호 및 예약; 렌즈 이동으로 촬영 차단 | 외부에서 같은 모드를 제어할 수 있는지 미확인 |
| 마이크 소리 전송 | 내장 마이크·스피커, 제조사 앱의 양방향 음성 | ONVIF 음성 역방향 전송 또는 제조사 인터페이스 확인 필요 |

### 개발 순서

1. 기기를 움직이지 않는 서비스·지원 기능 조회부터 진행한다. RTSP 포트가 ONVIF 포트라고 가정하지 않는다.
2. 회전 서비스·명령·정지·저장 위치 지원을 확인한다. 짧은 이동 테스트와 정지를 먼저 검증한 뒤 UI를 만든다. 상세 항목은 [기존 실기기 시험 메모](future-tests.md)를 따른다.
3. ON/OFF는 앱의 '사용 안 함', 사생활 보호 모드, 실제 전원 차단을 구분한다. 우선 카메라의 사생활 보호 모드를 제어할 수 있는지 조사한다. 완전히 전원을 끈 기기를 다시 켜는 것은 외부 전원 제어 등 별도 수단이 필요할 수 있다.
4. 마이크는 지원 코덱·인증·음성 전송 경로를 확인한 뒤 작은 음량으로 시험한다. 일반 RTSP 영상 재생만으로 마이크 전송이 가능하다고 가정하지 않는다.
5. 초기 마이크 UI는 '누르는 동안 말하기'를 우선 검토한다. 전송 대상과 상태를 분명하게 표시하고 버튼 해제·포커스 상실·창 닫기·연결 끊김 때 전송을 중지한다.
6. 실제 테스트로 지원이 확인된 기능부터 개발한다. 지원하지 않는 기능은 일반 버튼으로 제공하지 않는다.

공식 근거:

- [ipTIME C400GS 제품 설명](https://www.iptime.com/products/961): 회전·저장 위치·사생활 보호·양방향 음성. 외부 ONVIF 제어까지 지원한다는 근거로 확대 해석하지 않는다.
- [ipTIME 외부 RTSP 접속 안내](https://www.iptime.com/support/faq/26651): 외부 스트림 재생 지원.
- [ONVIF Profile T](https://www.onvif.org/profiles/profile-t/): 관련 기능을 지원하는 장치/클라이언트의 PTZ·양방향 음성 범위. C400GS의 해당 지원이 확인된 것은 아니다.

카메라 주소·계정·비밀번호는 계획 문서나 공개 이슈에 기록하지 않는다.
